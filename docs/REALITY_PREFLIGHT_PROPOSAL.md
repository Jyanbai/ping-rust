# Reality 零输入部署预检提案

日期：2026-10-01。状态：**提案，未实现**。

依据：MERGE_SHA `74b39c86d1065c1fb483c4c7c2f163976f120f2f` 的真实排查，详见 [实机验收追加记录](../COMPLETION_AUDIT.md)。VPS 同配置回环和 HK 客户端成功，大陆 OpenWrt/Passwall2 路径超时；用户授权加入唯一测试目标的临时直连例外后，大陆同配置请求成功。初次失败不改写。

## 可以在 VPS 本地发现什么

| 拟增加的检查 | 可以给出的结论 | 不能证明什么 |
|---|---|---|
| 选择 SNI 前分别检查 DNS A/AAAA 和目标 TCP/TLS，使用明确超时与证书校验 | 目标站在该 VPS/地址族是否能完成 TLS；记录耗时和具体失败阶段。一个候选失败时可探测下一个，全部失败则中止部署并解释。 | HTTP 非 2xx 不等于 TLS 失败；某地址族失败不能否定另一个地址族成功。 |
| 用本机网卡/路由地址与公网探测结果作比较 | 提示可能存在 NAT 或端口映射，需要核对外部地址/端口。 | 云平台的一对一 NAT 很常见，地址不同本身不构成部署失败；无法自动得知云控制台的映射规则。 |
| 部署后用原凭据发一次本地 Reality 请求 | 区分“配置可解析/服务 active”与“实际 Reality 数据面可用”。临时 loopback 客户端入口必须带认证。 | 回环成功不能证明外部端口可达、云安全组开放或客户端路由正确。 |
| 读取本机防火墙与监听状态 | 发现缺失监听、明确的本机过滤规则；报告本机观察。 | 不自动修改防火墙；不能代替云安全组或客户端网络的检查。 |
| 比较可用的可信时间来源与本机时间 | 提示 Reality 时间校验可能受影响；明确列出同步状态和误差证据。 | `NTPSynchronized=yes` 不能证明另一台客户端的时钟准确；不能仅凭某个差值认定握手超时原因。 |

这些检查应先定义超时、失败处理和输出契约，再决定实现方式；本提案没有确定产品默认行为。若采用额外客户端二进制，必须固定版本、校验官方摘要，并明确首次安装的耗时/下载成本；也可评估在进程内实现有认证的协议自检。

## 外部路径检查需要独立视角

单台 VPS 无法可靠推断大陆路由器是否运行透明代理，也无法只靠客户端 TCP connect 判断 SYN 是否到达自身。可设计一个显式选择的外部验证命令：

1. 在用户控制的外部客户端使用导出配置进行认证请求。
2. 同时在 VPS 观测这个端口收到的连接，区分未到达、TLS/Reality 拒绝和后续出站失败。
3. 若本地数据面成功、外部没有收到报文，输出检查项：导出地址/外部映射端口、云安全组、路由器透明代理、客户端所在网络。不要自动断言 GFW、NAT、SNI 或上游兼容故障。
4. 建议对测试服务器地址配置有边界的 DIRECT 例外或切换独立客户端位置；环境变更应由用户控制，不自动停用整台路由器的代理服务。

零输入安装的成功信息可分别呈现“配置校验”“本地监听”“本地 Reality 数据面”“外部验证”。尚未执行的外部验证必须写“未验证”，不能从 systemd active 推导出来。

## 记录与验收标准

- 记录时间、命令模板、地址族、阶段、耗时、退出码以及脱敏错误。公网地址仅记一致/不一致；认证、密钥、short ID、URI 和二维码不进入日志或仓库。
- 保留失败记录，修正环境后的结果另行追加。
- 未来实现前设计可复现用例：目标 TLS 超时、AAAA 缺失但 IPv4 成功、网卡私网/公网探测不同、回环成功但外部无 SYN、客户端 TCP connect 被透明代理提前接受。
- 本提案不调整 shoes pin、不修改 Reality 凭据或关闭协议校验，也不解决后续 Hot Reload 默认 Release 路径的独立验收失败。
