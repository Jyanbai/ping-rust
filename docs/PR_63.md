# feat: 默认检测并选择 Reality 与 ShadowTLS 目标

关联 #63。

## 改动

- 编译时嵌入 `data/reality-sni-candidates.txt`，按文件头规则忽略空行与注释。新节点并行检测所有候选，每个候选整体限时 3 秒，使用系统 DNS、TLS 1.3、仅 `h2` ALPN 和 webpki 公共根证书校验；不发送 HTTP 请求、不启动外部进程。
- 从握手最快的至多 3 个可用目标中随机选一个。接入 `add/a`、首次部署、普通与高级菜单；覆盖三种 Reality 和 SS + ShadowTLS v3，ShadowTLS 默认握手目标为 `<SNI>:443`。
- 交互时显示逐项结果；非交互仅向 stderr 输出一行摘要，stdout 分享链接约定保持。全失败时终端支持格式校验后的手动输入与 `0` 取消；非终端和安装入口的 bootstrap 直接报错，不读取 stdin。手动 SNI 只检测一次，失败只警告仍使用；普通 TLS 证书名称不检测。
- `generate` 始终不检测，未指定时从同一名单随机选，并向 stderr 提示“未做连通性检测”。
- Trojan Reality、AnyTLS Reality 补齐“更改 SNI”；复用现有配置事务、服务验证和失败回滚。默认 `<旧域名>:443` 目标同步改名，自定义目标保留。升级不修改已有节点。
- 覆盖服务端、状态、URI、终端二维码、Mihomo 和 sing-box 的一致性。AnyTLS Reality 不支持的标准 URI/QR、Mihomo 导出，以及 ShadowTLS 不支持的标准 URI/QR 均继续明确拒绝。
- 更新 README 和 `--server-name` 帮助。

依赖仅将锁文件中已有的 `rustls =0.23.46`、`tokio-rustls =0.26.4`、`webpki-roots =1.0.10` 提升为直接依赖，以实现无 HTTP 的 TLS 握手和证书校验；没有新增 crate 或升级锁定版本。TLS 1.2 feature 用于本地测试旧版本服务端，探测客户端仅启用 TLS 1.3。
